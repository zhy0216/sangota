# todos — 对标《杀戮尖塔》的功能缺口

每个文件一个功能，按「优先级 / 依赖关系」排序。

**完成的任务，文件名加 `-done` 后缀**（`03-card-upgrades.md` →
`03-card-upgrades-done.md`），索引里打 ✅。所以 `ls todos/` 本身就是进度看板。

文件内统一结构：

- **现状** — 当前代码里有什么、在哪一行
- **原版行为** — 《杀戮尖塔》怎么做的
- **设计方案** — 本项目（三国题材）打算怎么做
- **数据结构** — 需要新增/修改的类型
- **实现步骤** — 可直接开工的清单
- **验收标准** — 做完怎么算过
- **依赖** — 必须先做哪个

## 已知遗留

归档（✅）只代表该条目的主体验收项已在代码里核实通过。下面是**逐条对过验收标准后
仍未达成的部分**，按 todo 编号列出。◐ 表示条目未归档。

归档的门槛是「该条目自己范围内的验收项全部做到」。只被别的 todo 卡住的验收项
（几乎全是「[08 存档](08-save-resume.md) 能恢复 X」）记在下面并归档；
**自己范围内没做完的一律不归档**——阶段三这么拒过 15，阶段五这么拒 17。

### [09 多幕](09-acts-and-progression-done.md) ✅ — 阶段五归档

八条验收里七条已在代码与 `tests/acts.test.ts` 里逐条核实：Boss 宝箱三选一 →
幕间 → 新地图、三幕地图各自可复现且互不相同、二幕数值分层、地图顶部提前

  `run.act` 确实会变（`advanceAct` 是唯一写它的地方，有测试守着），

  **08 落地时必须回来补这半条。**
- **事件池与商店库存没有按幕分池**，仍是全局池。这是 09 的「设计方案」与

  二幕 8.5 场只见到 6.1 种。数字与诊断在 todo 文件末尾。
- **12 个奇遇撑不满四幕**：第三幕 20 个 event 节点见不到一种新的。
- **「胜利结算」是占位屏**。`InterludeScene.paintVictory()` 只印体力/资财/

  （触发条件是 `actExit(run) === 'victory'`）。

### [17 多武将](17-multiple-heroes.md) ◐ — **拒绝归档**

赵云与诸葛亮已上，选将、专属卡池、按武将过滤的奖励/商店/事件都做完了。
但有两条验收标准落在 17 自己的范围内且**确实没做**，与阶段三拒绝归档 15 的
理由同级：

- **赵云的连击数没有上战斗 HUD。** `src/scenes/` 与 `src/ui/` 全目录 grep
  不到一次 `attacksThisTurn`。状态早就在（`startPlayerTurn` 归零），缺的只是
  `CombatScene` 里的一处读数。卡面数字本身是活的（`describeCard` →
  `previewValues`，`tests/heroes.test.ts` 里「打两张攻后七探盘蛇显示 10」有断言），
  唯独玩家看不到当前连击数。
- **没有任何限定武将的可掉落遗物。** 闸门是实的——`unowned()` 会按
  `RelicDef.hero` 过滤，是全项目唯一检查遗物归属的地方——但 `relics.ts` 里
  没有任何一条声明 `hero`，所以「赵云专属遗物只在玩赵云时出现」这条无从成立。
- **卡池只做了三分之一。** 实现步骤第 3 条要 20+ 张：关羽 21 张，
  赵云 9 张、诸葛亮 9 张。后果可量：坊市一次上 4 张本武将牌，赵云一进坊市
  就看到自己 9 张里的 4 张。
- 另有一处措辞偏离（非阻塞）：验收写「战斗奖励只出本武将的牌，加上 colorless」，
  实际 `COLORLESS_POOL` 只由坊市与奇遇发放，战斗奖励不含无色——与原版一致，
  但与验收字面不符。
