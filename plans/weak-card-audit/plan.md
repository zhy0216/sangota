# 弱势与低选取价值卡牌排查

**状态：已完成实施。** 用户在初始规划后要求完成本计划，任务 1–7 均已执行。最终牌值、实验取舍、异常样本和验收结果见 [results.md](results.md)，完整 648 行成对比较见 [comparisons.csv](comparisons.csv)。下文发现清单保留原始基线；其中血染征袍的最终方案改为自伤 **3 → 1**、伤害保持 **10／14**，未采用初始加伤候选。

## 意图

确认当前项目是否有明显偏弱、被同类牌挤压，或玩家很难找到选取理由的卡牌，并给出可追溯的依据和后续调整方案。

**结论：有。已开放武将优先复核「枪挑高览」「万人敌」「横扫千军」「血染征袍」；制作中的诸葛亮另有「伏兵」被「屯田」同条件压过、「观星」抽牌后没有气可用等问题。** 不能把所有模拟低分牌都当成弱卡：现有 AI 不充分理解多段攻击、连击准备和长期收益，仓库也没有真实玩家的“出现次数—选取次数—打出次数”数据。

分析基线：`f6f4c01`。覆盖全部 159 张正向卡牌定义，包括基础牌和「锦囊」；主清单针对关羽、赵云的 102 张奖励牌与 5 张无色牌。诸葛亮的 42 张奖励牌单列，因为 [heroes.ts](../../src/data/heroes.ts) 中明确设置了 `wip: true`，常规选将入口不可选。7 张诅咒和 5 张状态牌不计入“应该加强的弱卡”。

初始规划阶段只新增本方案。后续实施修改了十张卡、诊断工具与相关回归；未创建任务队列，未改变存档结构。

## 目标 / 非目标

目标：

- 找出同池同定位下缺少优势的牌，并同时比较普通版、升级版。
- 区分数值不足、触发门槛过高、合理的特定构筑用牌和模拟器误判。
- 给每个优先候选提供具体对照、反例、实验方向及验收条件。
- 为后续调参保留可复现的基线，避免仅凭 AI 排名统一加数值。

非目标：

- 不删除卡牌、不拆 `todos/`、不启动执行 agent；后续用户已授权实施本方案中的平衡调整。
- 不调整敌人、掉落概率、武将开放状态、美术和商业化内容。
- 不把“比基础攻击强”当成奖励牌足够好的唯一标准，也不要求所有牌适合所有牌组。
- 不把跨武将的费率差异、正常的稀有度差异直接认定为设计错误。
- 不宣称已经测得玩家实际选取率或通关率。

## 排查依据与已完成验证

### 实际规则

- [engine.ts](../../src/combat/engine.ts)：通常每回合 3 气、抽 5 张、手牌上限 10；牌先扣费并离开手牌，再结算效果；连击数不计本牌；X 费使用当前全部气。
- [relics.ts](../../src/combat/relics.ts)：关羽首张攻击的 +3、赵云第二张攻击的 +4 会加到该牌的**每一段伤害**。因此同费用的单段与多段牌必须带起手宝物比较。
- [statuses.ts](../../src/combat/statuses.ts)：神力按伤害段数增加，身法按主动获得护甲的次数增加；重甲是在回合末获得护甲，不是每次攻击固定减伤。
- [cards.ts](../../src/combat/cards.ts) / [heroCards.ts](../../src/data/heroCards.ts)：牌池按武将隔离，且声明顺序参与种子奖励结果；不能靠重排、删除定义解决重复定位。
- [shop.ts](../../src/rooms/shop.ts)：普通、罕见、稀有、传奇牌的基础售价分别为 26–32、40–48、78–92、126–152。稀有牌的“只在极少情况下有用”还有购买机会成本。

### 原有逐卡模拟

执行：

```bash
bun run eval -t '卡牌边际价值'
```

直接使用 [evaluate.sim.ts](../../sim/evaluate.sim.ts) 的现有仪器：一幕装备、满血、随机选取 6 张奖励并随机升级 3 次、1 件额外常见宝物；每张被测牌额外加入 **2 张未升级副本**，轮换一幕三首领，每行 300 场，策略为 `greedy`。每个武将都有相同种子配方的无额外卡对照。

共 159 个卡牌测试行与 3 个对照行，约 48,600 场战斗。该测试通过，用时约 50 秒；其余评估项及报告落盘项未运行。控制台基线胜率约为关羽 64%、赵云 48%、诸葛亮 52%。下文 Δ 都是这一实验的**胜率差，单位为百分点，按原报告取整**，不是玩家统计，也不是概率上限。

### 仪器的实际盲区

1. **攻击只比较单段伤害。** `sim/policy.ts:106` 使用 `previewValues(...).D`，没有乘 `T`；`threat` / `adaptive` 的斩杀判断也有同类问题。实测赵云已打出一张攻击、剩 3 气时：「力斩五将」为 `9 × 5 = 45`，「突阵」为 `10 × 1 = 10`，`greedy` 却选择「突阵」。所以「力斩五将」「七入长坂」等低分尤其需要复核。
2. `greedy` 先攻击，再防御，最后才尝试其他牌；它不会可靠地先回气、先叠护甲或先放能力再打收尾牌，也不按整回合可兑现收益排序。
3. 测试是“加两张到随机牌组”，不是“选一张与跳过相比”，也不是等牌组大小替换。增加厚度、重复能力牌和牌序变化都混入了 Δ。相同种子不代表改变牌组长度后每次抽牌一一对应。
4. 首领场景遗漏大量群战价值：一幕首领里张宝会分裂，但仍不能代替完整的普通群怪、召唤精英与后期测试。满血开场也无法代表跨战斗续航。
5. 300 场只能筛选明显信号；不能按几个百分点的差异机械排序。小于约 10 个百分点的变化尤其不宜单独作为改牌依据。
6. 诸葛亮扫描中出现保护退出：屯田 1 次、安居平五路 2 次、八阵图 3 次、井田法 2 次。总测试通过不代表所有行均完成正常战斗；这些行须先复核退出原因，不能直接作平衡验收。

### 玩家行为数据的边界

[history.ts](../../src/state/history.ts) 的 `totals.cardsTaken` 来自结算时的最终牌组计数，包含起手牌，缺少奖励出现次数，也看不到中途移除的牌和逐卡打出机会。因此它不能用来证明“玩家从不选某张牌”。本方案所说“低选取价值”是规则分析和模拟信号支持的推断。

#### A1. 枪挑高览：不是不能触发，而是触发后的溢价太小

位置：`src/data/heroCards.ts:1729`；对照「力斩五将」在同文件 `:370`。

- 未满足条件时，15 伤 / 3 气只有每气 5 伤；升级后也只到 18 伤。
- 满足三攻条件后，同回合这张牌仍需另付 3 气。用起手牌演示：`突阵 → 突阵 → 龙胆` 已满足三攻，但只剩 1 气，实际 `playCard` 拒绝打出「枪挑高览」。
- 存在可行路径：`突阵 → 龙胆 → 疾刺 → 枪挑高览`，疾刺返气后能支付最后的 3 气。不能将其写成“无法触发”。
- 即便已经满足三攻，裸神力时普通版相较「力斩五将」只多 5 伤，升级版只多 **1 伤**；后者还更吃神力加成。三攻以后的高览也不再享受赵云“第二张攻”的宝物加伤。
- 保留价值：单段攻击面对暴怒敌人比五段更安全。这是差异，但不足以自动证明当前基础值和门槛合理。

建议：保留单段收尾身份，先单独实验**费用 3 → 2，其余不变**。若仍需改善，再比较降低触发门槛的另一套方案；不要一次同时降费、降门槛、加伤害。需与「七探盘蛇」「长坂坡」「力斩五将」一起比较，确保每张各有适用场景。

#### A2. 万人敌：同稀有同费用的竞争最直接

位置：`src/combat/cards.ts:126`；对照「水淹七军」在 `:350`。

- 不计修饰，11 / 15 群伤已经低于水淹的 12 / 16。
- 引擎实测：两名存活敌人、关羽首张攻击，万人敌各打 **14**，水淹各打 **18**；有 2 神力时分别为 **16** 与 **22**。有牌可抽且结算后仍有至少两名敌人时，水淹还抽 1 张。
- 升级未解决定位问题：首攻时 18 对 22，仍落后。
- 反例：多段可能额外喂养暴怒；负神力、逐段取整等也会改变比较。因此应称“常态被压制”，不是严格任何状态下的下位替代。
- 水淹七军有解锁门槛（`src/data/unlockTracks.ts:38`），万人敌在尚未解锁水淹的新账号里仍提供群伤入口。不可直接移出牌池。

建议：保留“稳定单次群攻”，实验基础 / 升级伤害 **15 / 19**。这是待验证的起点：携起手宝物首攻时与水淹约打平，水淹仍保有额外神力成长和抽牌价值。也要对照 1 气群攻「偃旗掩杀」，防止调整后挤压其他牌。

#### A3. 横扫千军：群伤用途存在，启动成本过高

位置：`src/data/heroCards.ts:571`；对照「拒马」`:1158`、「常山赵子龙」`:1527`。

- 未触发时，2 气只对每个敌人造成 6 伤；单敌时等同起手攻击的基础伤害，却多花 1 气。
- 触发要先打 2 张攻击，然后仍留 2 气；典型 `突阵 → 突阵` 后仅剩 1 气。需要零费攻击或回气牌铺垫。
- 恰好作为第二张攻击时，可以吃起手宝物 +4，但此时又不满足“已打出 2 张”的强化条件；两个加成窗口错开。
- 「常山赵子龙」同为 2 气，无条件已是 10 / 13 群伤，达到横扫的强化数值；它更稀有，因此属于跨稀有度挤压证据，不能称严格同档下位。
- 「拒马」只有 1 气，适合护甲支线，但输出也有条件。不能因为横扫弱就把它直接降到 1 气，否则会转而挤压拒马。

建议：保留 2 气连击群攻，先实验基础 **9 / 12**、强化 **12 / 16**，与常山、拒马进行群战对照。若设计需要更明显的差异，可另测强化时少量返气或抽牌，避免同时叠加全部增益。

#### A4. 血染征袍：自伤应换来足够明显的回报

位置：`src/data/heroCards.ts:269`；对照「挺枪」`:111`、「杀透重围」`:1407`。

- 已有一攻时，血染 10 对挺枪 9，只多 1 点；升级后 14 对 12，只多 2 点。都是 1 气，但前者每次掉 3 体力且更稀有。
- 携赵云起手宝物的第二张攻击，引擎实测为 **14 伤并掉 3 体力** 对 **13 伤且不掉体力**，判断不因宝物翻转。
- 有价值的场景是第一张就需要无条件斩杀，或主动进入半血收益区；还可搭配「杀透重围」等回血。但这些条件都不能当成免费补偿。
- 自伤通过正常伤害管线，可消耗天佑；对护主冲阵 / 天佑支线尤其需要提醒其真实代价。濒死时也可能先自伤致死、后续攻击不再发生。

建议：先实验保持 1 气、3 体力代价，将伤害改为 **12 / 16**；另设“降低自伤”的独立方案作对照。验收看跨战斗净失血和抢杀收益，不能只看一次满血首领战。

| 卧龙出山 `heroCards.ts:2031` | P2 / easy | 与「六出祁山」同为稀有、2 气、消耗，神力同为 2 / 3，但只给 2 张锦囊；后者给 4 / 5 张。通常额外锦囊意味着更多护甲、抽牌和消耗触发。顺序不同，手牌接近上限时多造牌也可能有成本，故不是无条件严格支配。 | 拉开定位；普通手牌容量下必须能解释为何会优先选卧龙出山。 |
| 巧舌 `heroCards.ts:2818` | P2 / easy | 1 气群体破绽 2 / 3；无色「离间计」同为罕见、同费、可循环，同时给同量破绽和怯战。通常价值更全面。无色获取渠道不同，额外减益与敌方护身符的顺序也有差异。 | 按“奖励入口 vs 商店无色入口”复核选取价值，不仅凭跨渠道比较就直接加强。 |
| 火烧藤甲 `heroCards.ts:2436` | P2 / medium | 稀有 2 气、消耗，消耗堆 ≥5 时 24 / 28，否则 12 / 14；罕见「焚聚」同费同门槛，可循环，热态 20 / 26、冷态 11 / 14。升级版的一次性代价仅换到热态多 2 伤。 | 拉大一次性爆发与循环输出的差别。保留消耗触发的协同价值；原模拟为 +7，属于同类定位问题而非已证实的负收益牌。 |

### D. 不应因扫描低分直接判弱的牌

| 卡 / 类型 | 本次发现的反证 |
| --- | --- |
| 长坂坡（−13）、七入长坂（−14） | 连击段数、神力、回气与抽牌需要准备顺序。原 AI 单段计分且不会先铺三攻，须先有能打出组合的对照策略。 |
| 枪出如龙（−17）、拒马（约 −10） | 属护甲前置攻击。AI 倾向先攻击再防御，容易反复使用冷态；应测试空营计等先防后攻。 |
| 银枪（−8） | 1 气 5 / 8 伤并补一张牌，有维持攻击计数的直接用途；低分不足以证明该循环组件应加强。 |
| 观阵（−7）及整军 / 消耗能力 | 0 气可循环抽牌、先放能力再使用配套牌的收益都受策略影响；加两张还可能扰动已有牌组循环。 |
| 空营计 | 实际是“出这张牌时尚未攻击”，不是“本回合不能攻击”。实测先拿 11 甲再打两张攻击，11 甲仍在；不是天然与连击冲突的牌。 |
| 连环枪 | 虽然伤害低于更稀有的三进三出，赵云第二张攻击时仍有 `(3+4)×2=14`，高于突阵的 `6+4=10`。稀有度和每段宝物加成都不能忽略。 |
| 结营、敛众固守、八阵图、身在曹营 | 分别有升级降费、持续防御或关键回合保命用途；单场满血首领的低分不足以决定普遍加强。身在曹营的 2 层金蝉脱壳实际覆盖一个敌方回合，不能误算为两个。 |
| 基础攻击 / 防御 | 起手牌随构筑成长被替换是合理进程；本次不把它们加入奖励牌抬底任务。 |

无色池的五张牌都能说明具体用途，目前没有足够依据将其中一张列为首批弱卡。八阵图的即时启动代价可以观察，但不应只根据关羽 −4、赵云 −5 的结果就改动。

## 方案

### 1. 先完善诊断，再决定最终牌值

涉及 `sim/policy.ts`、`sim/evaluate.sim.ts`、`sim/runCombat.ts`、相关机制测试。

- 增加独立诊断策略或评估模式，保留当前策略与黄金快照的原始语义。至少正确识别多段总伤害、群攻目标数、支付后的可用气、攻击顺序和护甲前置。
- 对暴怒、死亡截断、分裂、过量护甲等情况，简单 `D × T` 仍不是最终收益；以实际引擎结算或明确边界的短序列评估复核。
- 为单张候选同时做：原牌组直接跳过、加 1 张、加 2 张、等大小替换同定位牌。升级前后各测，不把单张能力与重复两张能力混在一起下结论。
- 保留旧 `greedy` 作为“直觉拿牌”的参考；增加会使用该构筑的策略与手工序列作为另一端。两种结果分开报告。
- 原报告里出现 `aborted` 的行先解释、修复或标为无效，不能与正常胜负混用。

### 2. 最小场景矩阵

| 维度 | 必须覆盖 |
| --- | --- |

| 牌组 | 初始牌组加候选；一幕随机成长；有关联零费 / 回气牌的连击组；护甲反击组；关羽神力组；弃抽 / 消耗 / 洗牌组。 |
| 战斗 | 单敌、双敌、三敌；`m2` / `m5` 群战、`e2` 暴怒、`e3` 召唤、一幕三首领、二三幕及终章代表战。 |

同种子进行成对比较，报告差值及不确定性。先用 300 场筛选；只有差异接近噪声且会影响决策时再扩大样本。构筑组件的目标是至少有一个合理、非极端的选取场景，不是每种牌组都必须赢过跳过。

### 3. 首批调整范围

首批只处理 A 类四张。上文数值是各自的**实验候选**，不是已验证的最终配置；每次只改变一个方案的关键变量，保留修改前结果。

- 万人敌：补单段群攻的基础回报。
- 横扫千军：补冷态与连击群攻回报，同时维持拒马、常山赵子龙的定位。
- 枪挑高览：让准备后的收尾费用与回报更合理。
- 血染征袍：让自伤换到可感知收益，守住跨战斗失血成本。

B 类先补场景证据，不自动进入调参；C 类作为诸葛亮上架前的独立范围；D 类需要先排除仪器误判。

### 4. 数据、文案和兼容约束

- 保留卡牌 ID、所属武将、牌池声明顺序、基础牌组与 RNG 调用契约；优先在原定义内调整效果。
- 普通版、升级版、预览文字与实际结算一起核对。现有注释存在旧数值，例如偃月斩注释写 24、定义基础实际为 18，证据以当前定义和引擎为准。
- 若改变费用，检查宝物按印刷费用判断的加伤 / 减费 / 复读条件；尤其不要把 X 费按实际支付当成固定大费牌。
- 验收现有黄金快照。只有能明确追溯到计划内牌值的变更才处理对应快照，不能以全面重录掩盖规则或出牌策略变化。
- 不为本次排查新增玩家联网埋点。未来若验证实际选取行为，须记录 offer、take、skip、remove 及使用机会，并控制武将、进度、解锁条件；当前的最终牌组计数不能代替。

- 通过只读 Bun 脚本直接调用现有引擎复核：万人敌与水淹的每段宝物加成；血染与挺枪的净体力代价；高览的不可支付与可支付序列；伏兵 / 屯田冷态热态和升级值；观星剩余气为 0；回枪单敌单段无减伤；空营计先防后攻可行；AI 对 45 伤力斩与 10 伤突阵的错误排序。

## 风险与假设

- 默认用户关注正常可玩内容的选取价值；制作中的诸葛亮作为附录，不把其问题算成已开放角色故障。
- “低选取价值”仍是设计推断；缺少真人选牌与操作数据，不能下“无人使用”的统计结论。
- 神力、起手宝物和复制效果按段放大；把单段伤害调到多段总和并不意味着成长率也相等。回枪、重甲与主动格挡的来源也不能混算。
- 解锁前后、不同武将和获得渠道会改变同类牌的竞争关系。万人敌在新账号中的群攻入口应保留。
- 多次扩池已有能力配套，不能沿用旧注释中“没有联动组件”的判断。弃牌、消耗、洗牌类的额外代价也可能就是其收益来源。
- 普通伤害、资源和效果测试通过只证明实现符合当前定义，不能证明卡牌平衡合理。
- A 类原文数值是初始实验候选；最终选择与模拟结果见 results.md，血染采用降低代价的另一方案。测试通过不等于整体平衡已完成。
- 不需要额外信息即可完成本次实施。诸葛亮开放节奏、后续整体平衡和是否引入行为统计仍属后续范围。
