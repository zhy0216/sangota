# 弱卡排查实施结果

计划的 1–7 项已完成。基线为 `f6f4c01`；最终修改 10 张卡，保留所有卡牌 ID、所属武将、稀有度、牌池顺序和起手配置。诸葛亮继续保持 `wip: true`。

完整对照见 [comparisons.csv](comparisons.csv)：21 张候选、54 个场景、每版 648 行比较，每行 300 个成对种子。这里的数值是模拟策略的结果，不能代表真人选取率。

## 血染为什么没有采用原计划的加伤值

分别测试两套独立方案，没有同时降自伤和加伤：

- A：自伤仍为 3，伤害提高为 12／16。
- B：伤害仍为 10／14，自伤降至 1。**最终采用 B。**

以下是 `tactical`、加入一张、连续经历 `m1 → m2 → e1`、体力跨战保留的结果。ΔHP 是相对跳过的最终平均体力差，失败样本也包含在内。

| 版本 | 普通版 ΔHP | 升级版 ΔHP | 普通版 Δ胜率 | 升级版 Δ胜率 |
| --- | ---: | ---: | ---: | ---: |
| 原版 | −7.78 | −6.85 | −8.3 pp | −6.7 pp |
| A：加伤 | −8.06 | −4.95 | −8.0 pp | −3.7 pp |
| B：降自伤 | **−2.33** | **+0.85** | **−2.3 pp** | **0.0 pp** |

加伤让策略更愿意反复使用，却没有解决普通版连续掉血。降低自伤改善了续航，同时保留即时斩杀用途。普通版连续战斗相对跳过的胜率区间仍覆盖零（−6.7 至 +2.2 pp），因此不能说它已经适合所有牌组。升级版连战 ΔHP +0.85 是描述性均值，不是已证明稳定回血。

最终方案另复跑了血染、高览、横扫、顺平侯的全部场景，覆盖会被血染变化影响的赵云随机牌组。其余候选场景属于其他武将或不包含血染的固定牌组，可以复用已完成的结果。CSV 的 `final_source` 标明每行来源。

## 场景证据

下表均为 `tactical`、普通版加入一张相对跳过，单位 pp 是胜率百分点。区间是**最终版本相对跳过**的区间，并非“改动前后差值”的区间；各版跳过对照分别计算。

| 卡 / 场景 | 原版 Δ胜率 → 最终 | 最终区间 | 原版 ΔHP → 最终 |
| --- | ---: | --- | ---: |
| 万人敌，一幕三首领 | −5.0 → +0.7 | −6.3 至 +7.6 | −2.36 → −0.20 |
| 万人敌，起手单敌 / 群战 | 0.0 → 0.0 | −1.6 至 +1.6 | +0.65 → +1.72 |
| 横扫千军，4 气连击群战 | +4.3 → +7.3 | +0.3 至 +14.1 | +1.18 → +2.56 |
| 枪挑高览，3 气连击 | −3.7 → +4.3 | −2.7 至 +11.2 | −2.04 → +3.33 |
| 枪挑高览，4 气连击 | +5.7 → +17.0 | +9.0 至 +24.5 | +5.03 → +9.89 |
| 血染征袍，护甲与天佑配置 | +9.7 → +13.7 | +6.6 至 +20.3 | +0.33 → +3.58 |
| 观星（WIP），锦囊构筑 | −5.3 → +1.0 | −4.5 至 +6.5 | −5.67 → +3.64 |
| 卧龙出山（WIP），一幕首领 | +29.3 → +31.0 | +23.4 至 +37.6 | +17.71 → +24.55 |
| 巧舌（WIP），锦囊构筑 | −2.7 → −0.3 | −6.0 至 +5.4 | −4.77 → +0.38 |
| 火烧藤甲（WIP），一幕首领 | +5.3 → +8.0 | +0.01 至 +15.7 | +2.09 → +3.24 |

这些结果支持改善方向与部分构筑用途，不能按小幅差异排名。随机成长牌组可能包含其他改动牌，所以它们反映本次整批改动下的选取价值；固定连击组等场景更便于隔离单卡影响。表格是探索性证据，没有对全部场景做多重比较校正。

绝营的主动护甲场景胜率差仍为 0，平均体力差约 −0.17；**没有证据证明补抽一张后就成为普遍强牌**。保留其针对主动护甲的定位，随 WIP 整体平衡继续观察。伏兵的依据主要是跨回合保留的功能差异，而非强行把护甲抬到屯田以上。

## 诊断工具与数据边界

- 新增独立 [tactical.ts](../../sim/tactical.ts)：最多向前四次出牌、保留六个候选状态，用真实引擎结算多段、群伤、暴怒 / 反刺、死亡、分裂、护甲与敌人行动。原 `greedy` / `threat` / `adaptive` / `random` 语义未改。
- 已回归旧策略把 45 伤力斩排在 10 伤突阵之后的反例，以及护甲前置、原 3 气与现 2 气高览的三攻顺序、死亡截断、缓存失效、RNG 不被搜索消耗、零费空转结束。
- [cardAudit.ts](../../sim/cardAudit.ts) 比较跳过、加入一张、加入两张、等大小换同类牌，普通 / 升级版、旧 / 新策略分别报告。默认每行 300 个匹配种子；每版实际执行 259,200 次样本试验，连续战斗试验包含最多三场。
- 覆盖起手、随机成长、神力、弃抽消耗洗牌、连击、护甲、锦囊；普通单敌 / 双敌 / 三敌、暴怒、召唤、三位一幕首领及二至四幕；3 / 4 气、半血、天佑、连续战斗。留气宝物另有实际跨回合测试。
- 新账号场景是过滤锁定卡 / 宝物后的合法牌组样本，**不是**真实浏览器解锁分布；水淹未解锁时用偃旗掩杀作同类对照。
- 机会统计计入牌组中所有同名副本。`readyPlays` 是出牌前满足条件次数，不是引擎中途触发次数；`unusedEnergy` 是使用过候选的回合末余气，不能全归因于该卡浪费。
- 胜率区间由成对“转胜 / 转败”比例的两个 97.5% Wilson 区间相减得到，作为保守的近似 95% 区间。即使 300 对样本全部同胜同败，也不会打印零宽度区间。ΔHP 和回合差仅报告描述性均值。
- 策略能看到其模拟出的种子抽牌，并使用长期状态的启发式分值；它不是人类模型，也不是最优策略或严格上限。没有新增玩家埋点。

## 保护退出

原版逐卡扫描的八次退出全部复现：均为诸葛亮对张宝的 `turnLimit`，不是程序卡死。把同一局上限从 60 延长到 180 后，均正常败北；敌方不断叠重甲，玩家能防守却难以破甲。没有提高全局上限来隐藏它们。

| 卡牌 | `evalcard-zhugeliang-` 种子后缀 | 延长后结束回合 |
| --- | --- | ---: |
| 屯田 | 65 | 61 |
| 安居平五路 | 65、98 | 69、68 |
| 八阵图 | 11、98、278 | 87、93、157 |
| 井田法 | 98、278 | 63、92 |

新的 648 行矩阵中，原版 11 行、最终版 13 行比较因任一对照臂出现退出而无效；均在诸葛亮相关场景。原版观星还出现了零气抽牌空转的 `noProgress`（`act1-bosses-283`、`tactics-205`）；最终矩阵没有 `noProgress`，剩余无效行均为回合超限。CSV 保留每行退出数量，原始 JSON 保留原因和种子。

[evaluate.sim.ts](../../sim/evaluate.sim.ts) 现在为无效行输出空胜率 / 差值，不进入池均值；[balance.sim.ts](../../sim/balance.sim.ts) 的逐武将展示也将退出格标为无效，不混入目标带比较。保护退出断言与默认策略均保留。不能用这些无效行给伏兵、观星、火烧藤甲等卡下平衡结论。

只更新了含万人敌的六份黄金快照。各份第一次差异均由万人敌伤害增加引起（裸值 +4；怯战 / 破绽会将差值变为 +3 / +6）；其余 31 份文件逐字未变。

实际验证：

- `bun run check`：最终牌值通过类型检查，**68 个测试文件、4,884 项测试通过**，包含全部黄金回放与确定性测试。
- `bun run build`：最终牌值构建通过。
- `bun run sim`：全套 **5 个文件、150 项通过**，十重天命 `threat` 24%（要求 15%–25%），二十重 5%。血染由加伤方案改为降自伤后，另用 `bun run sim -t 'per-hero balance'` 复跑三将全部 48 行；其余平衡套件只使用关羽牌池，不受该次赵云改动影响。
- `bun run eval -t '卡牌边际价值|评估报告落盘'`：最终版 2 项通过、2 项跳过；159 个卡牌测试行对应 149 个不同奖励 / 无色卡 ID，另有三位武将对照。最终万人敌 / 高览 / 血染的旧策略 Δ约为 +2.7 / +2.0 / +8.3 pp，横扫仍为 −18.0 pp，说明单一旧策略不能替代组合评测。
- 新矩阵、血染第二方案和基线文件回放均完成；数据写入 `out/card-audit/`。本次汇总保存到版本化的 [comparisons.csv](comparisons.csv)。

常规目标带仍有多个场景在带外；它们在仓库中属于调参提示，不是全部断言。通过验收不能解释为所有武将、卡牌和敌人的整体平衡已经完成。尤其诸葛亮仍为 WIP。

## 复现

每条命令都会保存完整卡牌目录、场景定义、原始配对样本和退出信息。默认 300 种子；`CARD_AUDIT_CARDS` 可按逗号分隔筛选卡牌，`CARD_AUDIT_N=2` 只适合冒烟检查。

```bash
CARD_AUDIT_BASELINE=plans/weak-card-audit/baseline-overrides.json CARD_AUDIT_LABEL=before bun run eval:cards
CARD_AUDIT_LABEL=after bun run eval:cards
CARD_AUDIT_CARDS=qiangtiaogaolan,xueranzhengpao CARD_AUDIT_LABEL=finishers bun run eval:cards
```

[baseline-overrides.json](baseline-overrides.json) 保存本轮十张卡的原定义，足以在当前提交恢复本次基线；也支持把工具生成的完整报告作为 `CARD_AUDIT_BASELINE`。本次为缩短运行时间按卡分组执行，最终 CSV 中 `after-*` 是第一套方案数据，`lowhp-*` 是血染降自伤后对相关场景的复跑。
